# Проверки хранения Analytics Service

Консольные интеграционные проверки используют настоящий PostgreSQL и не требуют LLM или RabbitMQ. Проверяются дедупликация при параллельной доставке, привязка чата, три условия формирования групп, изоляция тредов и команд, восстановление снимка, применение задач вместе с историей и outbox, откат при конфликте версии, повторы, риск и блокировки между соединениями. Для проверки издателя outbox используется MassTransit с транспортом в памяти.

Перед подключением к БД проверяются ограничения входного DTO и настроек: обязательные поля, границы длины и чисел, NaN/Infinity и зависимости между параметрами.

Также проверяются последовательности изменения задач, отсутствие изменений входного снимка при отклонении группы, версии, события и временные отметки. Для запуска только проверок валидации и применения изменений, без PostgreSQL:

```powershell
dotnet run --project tests/AnalyticsService.Checks/AnalyticsService.Checks.csproj -- --analysis-only
```

Из корня репозитория:

```powershell
docker compose -f tests/AnalyticsService.Checks/docker-compose.yml up -d postgres
dotnet run --project tests/AnalyticsService.Checks/AnalyticsService.Checks.csproj
```

По умолчанию используется `localhost:5433`, пользователь и пароль `teammemory`. Для другого сервера задайте переменную `ANALYTICS_CHECKS_CONNECTION` со строкой подключения. Пользователю нужно право создания БД.

Проверки создают отдельную БД с уникальным именем `analytics_orm_checks_<guid>` и удаляют её в `finally`. База из переданной строки подключения не изменяется. При аварийном завершении процесса тестовая БД может остаться на сервере.
